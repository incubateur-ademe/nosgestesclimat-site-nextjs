# ADR-001: Migrate the site design system to shadcn/ui + Radix

## Status
Accepted

## Date
2026-07-17

## Context
`nosgestesclimat-app` ships a hand-rolled design system under
`apps/site/src/design-system/` plus direct usages of legacy third-party
libraries (`react-modal`, `react-select`, `react-tooltip`) scattered through
the app code.

We wanted:
- One consistent set of accessible primitives based on Radix UI, following the
  shadcn/ui conventions already used for new work (CVA variants, `cn()` utility,
  `@/components/ui` components).
- The design system components kept as the project's public API — with their
  styles and props preserved — but re-implemented on top of shadcn/radix where
  the primitives are a good fit.
- `react-modal` and `react-tooltip` fully removed.

## Decision
Adopt shadcn/ui as the base layer for the design system.

### What was migrated
- **Button family** (`Button`, `ButtonLink`, `ButtonAnchor`,
  `ButtonLinkServer`): rewritten with `cva` + `buttonVariants` (shadcn
  pattern), preserving exported style class names.
- **Modal** (`react-modal` → Radix `Dialog`), preserving the `Modal`/`ConfirmationModal`
  public API (`isOpen`, `closeModal`, `ariaLabel`, `ariaLabelledBy`, ...).
- **Badge, Card, Separator, Alert**: re-implemented on the matching shadcn
  primitives, with design-system variants (colors/sizes) preserved.
- **Accordion / AccordionItem**: rewritten on Radix `Accordion`, preserving
  the item-based API, tracking, and chevron behavior. The orphaned
  `AccordionItemLegacy` was deleted (unreferenced).
- **TextInput**: renders the shadcn `Input` component internally; the design
  system style tokens are applied through `defaultInputStyleClassNames` and
  `cn()`. The public props (label, error, helperText, mention, debounce, ...)
  are unchanged.
- **InputGroup**: label now uses the shadcn `Label` (Radix) primitive.
- **Switch**: button options now render on a Radix `ToggleGroup` (`type="single"`),
  preserving the `options: {label, isSelected, onClick|href}` API and the
  segmented-control styling. Link options keep rendering as `<Link>`s in a
  `<nav>` (Radix `ToggleGroup` cannot render links).
- **CheckboxInput / SelectInput**: kept as native `<input type="checkbox">` /
  `<select>` elements. They are wired into `react-hook-form` via `register()`
  (which spreads `name`/`ref`/`onChange` and expects native `ChangeEvent`
  semantics); Radix `Checkbox`/`Select` use a different API
  (`onCheckedChange`/`onValueChange`) and render a `<button>`, which would
  break form registration. They now use the shadcn `cn()` pattern and the
  shared input style tokens instead of `twMerge`.
- **Tabs**: kept as a link-based navigation component (Radix `Tabs` is
  content-oriented — `TabsTrigger`/`TabsContent` — and would not fit the
  `items: {label, href, isActive}` API used by the page headers). Migrated to
  the `cn()` pattern.
- **BlockSkeleton / iframe skeletons**: replaced hand-rolled `animate-pulse`
  blocks with the shadcn `Skeleton` component.
- **FootprintSelector**: `react-select` → shadcn `Select` (Radix), preserving
  the two-option (carbone/eau) UI with emoji.
- **CookieConsentBanner**: `react-modal` → Radix `Dialog`, preserving the
  fixed-position banner layout, focus behavior, and testids.
- **Dependencies**: removed `react-modal` and `react-tooltip` from
  `apps/site/package.json` (no remaining imports).

### What was deliberately kept
- **ComplexSelect** (`react-select`): it performs asynchronous server-side
  search (`loadOptions` + `cacheOptions` + `isSearchable`) with a custom
  options format. Radix `Select` has no async-search support; replacing it
  would require a new debounced combobox implementation. Kept as-is for now,
  tracked for a follow-up.
- **Tabs** and **CheckboxInput/SelectInput**: see rationale above.

## Alternatives Considered

### Full rewrite of every input on Radix primitives
- Pros: maximal consistency, keyboard/native ARIA handling by Radix.
- Cons: breaks the `register()` integration of `react-hook-form` and the
  native `ChangeEvent` props of `CheckboxInput`/`SelectInput`; would require
  updating many call sites and tests. Not worth it for these two components.

### Keep `react-modal` / `react-tooltip`
- Pros: no work required.
- Cons: they are the last unmaintained pieces of the legacy UI stack, and both
  were fully removable (one remaining usage each). Removed.

### Replacing `ComplexSelect` with shadcn `Select`
- Pros: removes the last `react-select` import.
- Cons: no async search primitive in Radix; would lose the debounced server
  search UX. Rejected for this pass.

## Consequences
- Design system components remain drop-in compatible: same file paths, same
  exports, same props. No call-site changes were needed for migrated
  components.
- The `@/components/ui/*` directory (generated by `shadcn init`) is the new
  primitive layer; design-system components compose it instead of re-styling
  raw elements.
- `cn()` (shadcn `twMerge` wrapper) replaces direct `twMerge` usage in the
  migrated files.
- 179 unit tests pass and `pnpm typecheck` is clean. `react-modal` /
  `react-tooltip` are gone from `package.json`.
- Follow-up work: replace `ComplexSelect` once an async-search combobox exists
  (or build a small Radix-based combobox), and consider migrating the remaining
  design-system components (Carousel, Breadcrumbs, Loader, ...) opportunistically.
